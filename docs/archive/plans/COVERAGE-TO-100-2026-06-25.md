## networking (true_gap 70 — vpc 27, loadbalancer 12, dns 9, vpn 8, direct-connect 7, cdn 5, firewall 2)

The credit mechanic matters here (engine.py:1119-1123 + `_probe_reads` 298-343): WRITE steps
always record under the catalog key (need a real 2xx for C3); GET steps credit the catalog
key ONLY via `probe_reads` / explicit `params` / smoke — a plain `verify` GET records only
`lifecycle:step`. Several composed lifecycles "run" but the id-GET stays uncovered because
they use plain verify GETs.
