## 1. 이게 뭔가 (한 장 요약)

**Samsung Cloud Platform(SCP) Open API 1,416개 전체**를 두 축으로 자동
테스트하는 플랫폼이다:

- **AXIS 1 회귀** — "동작하는가?" 실제 리소스를 만들고 지우는 243개 CRUD
  라이프사이클 + 읽기 스모크. 목표 = 엔드포인트 커버리지 100%.
- **AXIS 2 컨포먼스** — "잘 설계됐고 AI가 쓰기 좋은가?" 정적 스펙 분석 +
  런타임 프로브 → 결함(findings)을 베이스라인 대비로만 알람.

특징: 엔지니어링 주체가 **AI 에이전트 팀**이다(로스터·운영루프 =
[`agent-team.md`](agent-team.md), 실행 정의 = `.claude/agents/`). 시나리오는
손코딩이 아니라 **리소스-태스크 모델**(`knowledge/formal/resources/`, 283노드)에서
**합성**되고, 도메인 지식은 [`knowledge/`](../knowledge/README.md)에 누적된다
(런타임 실측 사실 원장 `validated-facts.md` ≈ 4,000줄).

## 7. 새 사람 온보딩 (10분)

```bash
pip install -r requirements.txt          # (+ 콘솔 쓰려면: fastapi uvicorn jinja2 httpx croniter)
python -m spec.summary                   # 카탈로그 살아있는 수치
python -m regression.scenarios.validate  # 시나리오 무결성 (243/0err)
uvicorn controlplane.app:app             # 콘솔 → http://localhost:8800 (Catalog·Modeling·Testing·Reporting)
python -m pytest tests/offline -q        # 오프라인 게이트 (라이브 호출 없음)
```

- 자격증명은 **환경변수만** (`SCP_ACCESS_KEY/SECRET_KEY/REGION/ENV`; `.env`는
  절대 커밋 금지 — 템플릿은 `.env.example`).
- **실행 경로 2개**: 대화형은 콘솔 Testing(선택→pre-flight 견적→confirm→실행),
  CI 레인은 `.github/chat-heavy-request` push(chat-heavy.yml). `api-test.yml`
  push 자동화는 오너가 꺼둠(수동 dispatch만).
- AI 세션으로 이어받을 땐 프롬프트 한 줄이면 된다:
  *"Read `START_HERE.md` and continue per its instructions."*

## 8. 깨지기 쉬운 것 / 절대 규칙 (요약 — 정본: `CLAUDE.md` Hard Rules)

1. **안전게이트**: 뮤테이션은 기본 ON이 설계다 — opt-in은 "런 선택 + pre-flight
   confirm". read-only 강제는 `SCP_ALLOW_MUTATIONS=false`. heavy(과금)는 별도
   opt-in. **테스트 통과시키려고 게이트 만지지 말 것.**
2. **삭제는 오너태그 원장 경유만** (`core.registry`/reconciler) — 이름 추측 삭제 금지.
3. **워크플로 런은 한 번에 하나** — 이전 런(스윕 포함) 종료 확인 후 다음.
4. **쿼터는 예약 후 생성, 고갈 시 skip**(fail 아님) — 거짓 회귀 방지.
5. **기억보다 실측** — 수치/경로/플래그는 위 명령으로 재검증하고 쓸 것.
6. 배운 사실은 `knowledge/`에 **같은 커밋으로** 남길 것.
