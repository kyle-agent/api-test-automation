# V2 킥오프 브리프 — B안(재구조화)을 /v2 스트랭글러로

> 오너 결정 (2026-07-10): "이 세션(기존)은 현재 구조에서의 내부 엔진·실행순서·
> 커버리지 개선을 계속하고, **별도 세션이 B안을 /v2로 진행**한다."
> 이 문서는 그 별도 세션의 시작점이다.

   (페르소나 3인, 스크린샷 45장) 근거.

## 방식 — 스트랭글러 (fork/장기 브랜치 아님)

- **main 안에서 `/v2/…` 라우트(신규 라우터 모듈)로 병렬 구축.** 기존 화면은
  불변 — 기존 세션의 매일 런·수리와 충돌하지 않는 것이 이 방식의 존재 이유다.
- 오너는 `localhost:8000/v2`로 진행 중 실물을 보고 당일 피드백한다.
- 화면 단위로 완성 → 검수 → (마지막에) 스위치 전환 + 구 URL 리다이렉트 층
  (L3에 어차피 필수).
- 파일 경계 권장: `controlplane/v2/` (라우터·템플릿·정적) 신설, 기존
  `controlplane/*`·`console2/*`는 **읽기만**. 공용 데이터 접근은 기존
  로더/스토어 함수 재사용 (중복 구현 금지).

## 진행 순서 (CX-IA-DESIGN §5의 B 트랙)

1. **L1 설계 선행**: 서비스 상세의 데이터 계약 (발행 스냅샷 vs 로컬 관측 vs
   baseline 병합 규칙 — D2 결정과 연동) 문서화 → 오너 확인.
2. `/v2` 셸 (네비 골격: 질문 중심 6축 — 상황실/서비스/모델/실행/결과/도구,
   §4.2) + 출처·시점 배지 시스템을 **처음부터 전 수치에** (M1 원칙 내장).
3. **L1 서비스 상세** 첫 화면 (최빈 질문 "이 서비스 지금 어떤가" 2클릭).
4. L2 그래프 단일화 (오버레이 4종) — resource_graph.js 대개조는 기존 세션의
   console2 변경과 충돌 주의 (P2C-24가 console2.js를 크게 바꿈 — pull 후 시작).
5. L3 네비 재편·URL 정렬 → L4 legacy/ops.html 흡수 후 제거 (이식 검증 전
   제거 금지).
