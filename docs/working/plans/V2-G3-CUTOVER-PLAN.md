# G3 — 네비 전환(cutover) 계획안

> **되돌리기 비싼 유일한 단계라 오너 승인을 먼저 받는다.** v2 6축이 전부
> 실화면이고 LIVE 실행까지 실증됐으므로, 이제 v2를 기본 표면으로 올리고
> 구 URL을 리다이렉트하는 전환을 제안한다.

## 무엇이 바뀌나 (한눈에)

| 지금 | 전환 후 |
|---|---|
| `/` = 기존 홈 (구 네비) | `/` → `/v2`로 리다이렉트 (또는 v2 셸을 루트에 마운트) |
| 기존 네비: Modeling · Testing · Reporting | v2 6축: Overview · Services · Model · Runs · Results · Tools |
| 기존 화면이 1급, v2는 `/v2/**` | v2가 1급, 기존 화면은 `/legacy/**`로 보존(즉시 삭제 안 함) |
| 북마크·에이전트 하네스가 구 URL 참조 | **리다이렉트 층**이 구 URL을 v2 대응 화면으로 302 |

## 리다이렉트 매핑 (구 → 신)

| 구 URL | 신 URL | 비고 |
|---|---|---|
| `/` | `/v2` | 홈 |
| `/planning`, `/planning/*` | `/v2/model` | Modeling → Model (세부 탭은 쿼리 보존) |
| `/testing`, `/testing?service=…` | `/v2/run` (쿼리 그대로 승계) | 계획·실행. prefill 쿼리 유지 |
| `/reporting`, `/reporting/*` | `/v2/results` | 리포팅 → Results |
| `/reporting/coverage` (색칠지도) | `/v2/results` (해당 섹션 앵커) | 후속: 색칠지도 네이티브 |
| `/catalog` | `/v2/services` | 인벤토리 → Services |
| `/runs/{id}` | `/v2/runs/{id}` | 런 상세 (이미 대응 존재) |
| `/dashboard/**` | **유지(리다이렉트 안 함)** | 발행 대시보드 = 공유 표면(D4). 그대로 서빙 |
| `/knowledge` | `/v2/tools` (지식 링크) | 도구 축 |

**보존 원칙**: 기존 라우트는 삭제하지 않고 `/legacy/` 프리픽스로 살려둔다
(L4에서 이식 검증 후 제거). 리다이렉트는 302(임시)로 시작 → 안정 후 301 고려.

## 위험과 완충

| 위험 | 완충 |
|---|---|
| **에이전트 하네스가 구 URL로 API 호출** | `/api/**`는 **전환 대상 아님** — v2는 같은 `/api/*`를 쓴다. UI 라우트만 리다이렉트. API 무중단 |
| 북마크 깨짐 | 302 리다이렉트로 자동 이동 + `/legacy/` 탈출구 |
| 기존 세션(매일 런)이 구 화면 기대 | 기존 화면 `/legacy/`로 접근 가능 유지. 기존 세션에 URL 변경 사전 통지 필요 |
| 발행 대시보드 링크 | 건드리지 않음(D4) — 유일하게 리다이렉트 제외 |
| 롤백 필요 시 | 리다이렉트 층은 **1개 파일**(포워딩 라우트 테이블)이라 되돌리기 = 그 include 1줄 제거 |

## 실행 단계 (승인 시)

1. **리다이렉트 층 신설** (`controlplane/v2/redirects.py`): 구 UI 라우트 →
   v2 302 매핑. app.py에 include 1줄. **기존 라우트보다 먼저 등록**해
   섀도잉하되, `/legacy/` 원본은 별도 마운트로 보존.
2. **루트 마운트**: `/` → `/v2` (또는 v2 셸을 `/`에 직접). 셸 헤더의 "기존
   화면" 푸터 링크를 `/legacy/*`로 갱신.
3. **에이전트 하네스 URL 점검**: 저장소에서 구 UI URL을 하드코딩한 곳
   (docs·스크립트·`.claude/agents`) 정찰 → 신 URL 안내 주석/갱신.
4. **스모크**: 구 URL 20종 → 302 목적지 정확성 자동 테스트, `/api/**`
   무영향 확인, `/dashboard/**` 무리다이렉트 확인.
5. **기존 세션 통지**: URL 변경 + `/legacy/` 탈출구를 요청 문서로 전달.

## 오너 결정 요청

- **D-G3a**: 지금 전환할까, 아니면 v2를 `/v2`에 더 두고 관찰할까?
- **D-G3b**: 루트(`/`)를 v2로 넘길까, 아니면 당분간 구 홈 유지 + v2는 상단
  배너로 유도만 할까(더 보수적)?
- **D-G3c**: 302(임시, 되돌리기 쉬움) vs 301(영구, 캐시 강함) — 권고: **302로
  시작**.
- **D-G3d**: 기존 화면 `/legacy/` 보존 기간 — L4(이식 검증) 완료까지 권고.

승인해 주시면 위 5단계를 병렬 배치로 진행하고, 전환 직후 구 URL 리다이렉트가
실제로 도는 스크린샷/테스트로 보고한다.

## 실행 기록 — Phase 1 (2026-07-10, 오너 "작업해")

- **루트 전환 실행**: `/` → 302 `/v2`. 구 홈은 `/legacy/home` 로 보존.
  v2 footer·Tools 링크를 `/legacy/home` 으로 갱신. 엔진 테스트 1건(구 홈
  가정)을 `/legacy/home` 기준으로 갱신 — 양 스위트 통과(21/21·v2 전체).
- **나머지 리다이렉트 보류 이유(실측)**: v2가 아직 legacy에 의존한다 —
  `/planning/resources/map`(노드 에디터, v2 대체 없음)·`/reporting`(발행
  대시보드 핸드오프)·`/testing`(legacy 콘솔 핸드오프). 이들을 지금 v2로
  돌리면 v2 자신의 링크가 루프·파손된다. 따라서 `/planning`·`/testing`·
  `/reporting` 리다이렉트는 **L4(노드 에디터·잔여 기능 흡수) 완료 후**로 미룸.
- **되돌리기**: app.py의 `root_to_v2()` 제거 + `home()` 경로를 `/`로 복귀
  (2줄). 완전 가역.
- 검증: `/`=302→/v2, `/legacy/home`·`/testing`·`/planning/resources/map`·
  `/reporting`=200 유지 확인.
