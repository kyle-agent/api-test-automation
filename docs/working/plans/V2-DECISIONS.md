# V2 결정 기록 — D2·D6·D7·pre-flight (오너 확정)

> V2-KICKOFF.md의 "미결 오너 결정" 4건을 오너와 하나씩 논의해 확정한 기록.

## D2 — 판정성 수치의 기본 출처: **최신 발행본 단일 + 보조 칩** (옵션 A + 칩)

- 판정 헤드라인(회귀 유무·커버리지 KPI)은 전 앱에서 **최신 발행본만** 읽는다.
  `발행 @sha·시각` 배지 필수, 24h+ 노후 시 노랑 배지 + 값 회색화.
- 로컬 관측은 **"이 서버의 런"** 섹션에 격리. 헤드라인 옆에
  "발행 이후 이 서버 런 N건 →" 보조 칩(판정은 바꾸지 않음).
- 스냅샷 고정 화면은 과거형 표기("이 스냅샷 당시: fail 2"), 판정 재계산 금지.
- **오너 추가 요구**: 테스터가 로컬 결과를 공식 반영하는 **fold 동선을 v2 CX로
  설계**할 것 — 로컬 런에 "공식 집계 미반영" 상태 표시 + "공식 반영" 동선
  (반영 내용 미리보기 → fold 절차) + "CI로 재실행" 딥링크. L1 데이터 계약에 항목화.
- 오너가 확인한 멘탈 모델: 개선(시나리오·파라미터)은 커밋 → 다음 CI 턴에 자동
  반영이 기본 경로, fold는 즉시 공유가 필요할 때의 승격 지름길.

## D6 — Modeling 독립 의존그래프 탭: **제거**

- 오너 판단(원문 취지): 전체를 모아놓은 현재 탭은 너무 크고 복잡해서 전체
  그림을 보는 것 자체가 의미 없음. 의존이 가치 있는 순간은 **개별 리소스/
  서비스를 눌렀을 때** — 그 노드의 의존을 이해하고, 인간이 도메인 지식으로
  수정하는 맥락.
- v2에서 의존 정보의 표면: (1) 노드 에디터 인스펙터(**수정 가능**),
  (2) 서비스 상세의 미니그래프(이해용). 독립 탭 없음.
- 트래커 P2C-17("라벨만 개선해 유지")과의 문서상 상충은 이 결정으로 종결.

## D7 — 용어 정책 (2026-07-10 **개정**: 이름은 영어, 설명은 한국어)

> 개정 배경(오너 지적): "새 회귀"·"기지 실패" 같은 한국어 번역 조어가 오히려
> 해석 장벽 — 이 도메인의 자연어가 영어다. 초기안(한국어 1급)의 취지였던
> "신규자가 코드네임에 막히지 않게"는 한국어화가 아니라 정의 제공으로 달성한다.

- **네비·기능명·도메인 용어**(메뉴, 버튼, 섹션 타이틀, 컬럼, KPI 라벨): **영어 원어**
  — Overview · Services · Model · Runs · Results · Tools / New regressions ·
  Known issues · Verified (C3) · Called (C2) · Coverage · Leftover resources.
- **정의 툴팁·안내문·비고·empty-state**: **한국어 유지**.
- 부수 효과: 발행 대시보드(영어 위주, 공유 표면)와 용어 자연 정렬.
- 유지되는 규칙(불변): 코드네임(R2c 등)·모듈명·env명 화면 노출 금지, 은어
  첫 등장 정의 툴팁 의무, 구어체·비유·질문형 금지(격식 표현만), "상태" 단독
  한국어 라벨 금지, 제품명 "SCP API Regression" 단일, **용어 상수 모듈 강제**.
- **추가 (오너 지시 2026-07-10)**: 서비스명·카테고리·그룹 식별자 등 **데이터
  식별자는 원천 제공되는 영어 원문 그대로** — 한국어 번역·한국어 제목을 1급
  표기로 쓰지 않는다 (원천 데이터에 한국어 제목이 있어도 툴팁 보조로만).

### (참고) 초기안 — 한국어 1급 + 코드 괄호 보조 (2026-07-09 승인, 상단 개정으로 대체)

- 1급 라벨 한국어: 검증됨(C3) · 호출됨(C2) · 도달가능(C1) · 잔존 · 과금.
  은어 첫 등장 요소에 한 줄 정의 툴팁.
- 코드네임(R2c 등)·모듈명·env명 화면 노출 금지. 에러 문구 순화 + 기술 상세는
  접기/툴팁으로.
- "상태" 단독 라벨 금지 — 모델 상태 / 런 결과 / 커버리지로 어휘 분리.
- 제품명 "SCP API Regression" 단일화.
- 집행 장치: v2 셸에 **용어 상수 모듈**을 두고 모든 화면이 거기서만 라벨을
  가져다 쓴다. 표기 가이드 1페이지는 후속 산출물(오너 검수).
- **추가 (오너 지시 2026-07-10, G1 피드백)**: 타이틀·화면 문구에 구어체·비유·
  질문형 금지 — 격식 명사형만. 예: "상황실"→"현황", "지금 어떤가?"→"플랫폼
  현황", "돌리자"→"테스트 실행". 질문 중심 축은 IA 설계 개념으로만 유지하고
  화면 표기에는 쓰지 않는다.

## pre-flight — "LIVE는 항상 mutations ON"은 **의도된 정책** (확인됨)

- 오너: read-only 공유는 IA/CX를 주변에 보여주기 위한 열람용이었고, "실행을
  미리보기만 제공"하는 것은 의미가 크지 않음. **실제 플랫폼은 누르고 컨펌하면
  실행하는 것이 기본.**
- v2 실행 화면: mutations 토글 없음. 누름 → pre-flight 컨펌 → 실제 실행.
- read-only 기동(`SCP_ALLOW_MUTATIONS=false`) 서버는 **열람 모드**로 규정 —
  실행 버튼 비활성화 + "이 서버는 열람용(read-only)으로 기동됨" 이유 표시.
  (기존 콘솔의 하드코딩 오표시와 같은 "게이트 상태 거짓말"은 v2에서 금지.)

## D4 보강 — 발행 대시보드는 별도 페이지로 **유지** (오너 확정 2026-07-10, G2 피드백)

- 발행 대시보드(dashboard-data 정적 HTML)는 **많은 사람이 읽기 전용으로 공유받는
  대외 표면**으로 계속 발행·유지한다. v2가 이를 대체하지 않는다.
- 역할 분리: **v2 콘솔 = 팀 내부 조작·심층 분석**(실행·fold·서비스 상세),
  **발행 대시보드 = 공유용 공식 스냅샷**(링크 하나로 전달, 서버 불필요).
- v2의 서비스 상세 네이티브화(L1)는 콘솔 내 경험을 위한 것이며, 발행 파이프라인
  (dashboard/build.py)의 산출은 그대로 둔다. CX-IA-DESIGN §6 D4의 "장기 네이티브화로
  임베드 제거" 권고 중 **"발행본 축소·제거" 부분은 이 결정으로 기각**.
- 경계: 발행 대시보드의 디자인 수정은 v2 세션 쓰기 범위 밖(dashboard/** 는 기존
  세션 소관) — 필요 시 요청 목록으로 기존 세션에 전달한다.

## 설계 원칙 추가 — **패리티 우선, 발명 금지** (오너 피드백 2건, 2026-07-10)

- 서비스 상세("발행 페이지가 더 명확하고 보기 좋다")·Model 화면("기존의
  카테고리·서비스·리소스 접기가 더 편했다") 두 건 모두 같은 교훈: **이미
  검증된 화면이 있는 영역은 그 레이아웃을 v2로 이식(네이티브화)하는 것이
  기본**이고, 새 레이아웃 발명은 오너 합의가 있을 때만 한다.
- v2가 새로 가져가는 것은 셸·출처 배지·용어 규약·데이터 계약이지,
  이미 잘 작동하는 정보 설계가 아니다.
- 적용: 이후 화면(L2 그래프 포함)은 착수 전에 "기존 검증 화면이 있는가 →
  있으면 패리티 스펙부터"를 확인한다.

## D5 개정 — GitHub Actions 디스패치는 사용하지 않음 (오너 확정 2026-07-10)

- 오너: "CI 디스패치(GitHub Actions)는 런타임이 없어서 임시로 한 것 — 실제로는
  사용 안 함. 스케줄은 필요하지만 GitHub Actions로는 안 함."
- v2 반영: 실행 경로는 **이 서버(콘솔 엔진) 단일**. "CI로 재실행" 딥링크를
  "Rerun (plan)"(= /v2/run 프리필 → pre-flight)으로 교체, 서비스 상세의
  Run CTA도 legacy /testing 대신 /v2/run 프리필로 전환.
- **스케줄 방식은 미결** — GHA가 아닌 대안(예: controlplane 자체 스케줄러
  db.schedules+scheduler.py가 이미 존재) 중 무엇으로 갈지 오너와 후속 결정.
  그때까지 v2에 스케줄 UI를 만들지 않는다.
- 발행 파이프라인(현재 GHA의 dashboard 잡)이 어떻게 대체되는지도 이 결정의
  후속 논의 대상 — 발행 대시보드(D4: 유지)는 계속 발행돼야 한다.
