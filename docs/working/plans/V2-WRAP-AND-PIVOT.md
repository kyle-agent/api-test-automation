## 2. v1이 잃었던 장점 (선회 이유 — 오너 지적 누적)

v2를 만들며 놓쳤던 v1의 강점들 (이번 세션에서 오너가 반복 지적):
- 발행 서비스 상세의 **정보 밀도·명확성** (v2가 밋밋한 표로 후퇴 → 패리티로 복구했으나 이미 신호)
- Model의 **카테고리·서비스·리소스 3단 접기** (v2 평면 표가 불편)
- Runs의 **선택→DAG 계획 경험** (v2 초기안이 통째로 누락)
- 실행 화면의 **런타임 DAG 제거 판단** 등 v1이 이미 내린 좋은 결정들

→ 결론: v1의 정보 설계는 이미 여러 번 다듬어진 자산. **새로 짓기보다 접목이 옳다.**

## 3. 접목 후보 (v2 → v1, 가치 높은 것만)

우선순위순. 각 항목은 v1 화면에 **얹는** 방식(전면 교체 아님):

1. **출처 배지 3종 + empty-state 규율** — v1의 최대 약점(fail 2 vs run 없음
   모순)을 해소. v1 홈/리포팅의 수치에 발행/이서버/이런 배지 + "0 ≠ 관측없음".
2. **계획↔실행 연속성** (실행 뷰 B층) — v1 실행 화면 상단에 PLAN vs ACTUAL
   스트립(생성 n/~m·ETA 대비 경과·VPC 슬롯). legacy now-playing 위에 얹기.
3. **종료 후 다음 행동 카드** (실행 뷰 C층) — v1 런 종료 시 토스트 대신
   fail→트리아지 / +검증→fold / 잔존 상태 3줄.
4. **실행 중 이상 감지** (실행 뷰 A층) — 지연 의심·실패 군집(세마포어 대기와
   구분). 엔진 요청 #5(세마포어 이벤트) 선행.
5. **판정 시각 분리 표기** — 발행 시각 ≠ 판정 런 시각 문제(발행 산출물 불일치).
6. (검토) 용어 툴팁·정의 노출 방식 — v1 은어 장벽 완화.
