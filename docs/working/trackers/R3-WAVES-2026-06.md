## 합성-차단 클래스 (노드 notes에 사유 기록)

- **콘솔-전용 id** — alert/event-rule(servicewatch)·cm-event-policy
  (cloudmonitoring)의 metric/namespace/event id는 카탈로그에 발견용 list
  GET이 없어 API로 알아낼 수 없다 → **M5 Planning 폼에서 owner가 콘솔의 실
  id를 옵션으로 입력**하는 경로가 정답 (RESOURCE-MODEL-PLAN §3).
  cm-event-policy는 `productResourceId`만 API 발견 가능 —
  cm-account-resource lookup 노드 + X-ResourceType 헤더로 진전(헤더 수용
  확인, run 27401527554)했으나 계정에 모니터링 대상 VM이 없어 404 → heavy
  윈도우에서 서버 생성 후 재시도.
- **cloud-ml 체인** — image lookup 노드까지 배선해 **전 체인 합성 완료**
  (`gen-cloudml-chain`, 24스텝)이나 **SCR 인증키(콘솔 발급 credential) +
  heavy 게이트**에 막혀 disabled(gated-ready) 상태. owner 힌트(2026-06-12):
  SCR docker 인증이 **기존 SCP access/secret key일 가능성** →
  `regression/scr_docker_probe.py` 1-step 실험을 워크플로 run-request
  `docker_probe=true`로 배선. 1차 verdict: import 수정 후 실행됐으나
  registry create가 quota 403(1EA/가시성, PF-10)으로 **INCONCLUSIVE** —
  Running 레지스트리를 빌려 쓰는 fallback 추가, rev 3에서 재실험.
- **owner 범위 제외** — archivestorage는 **영구 제외**(전용 인증키 미발급,
  waiver 25/25), Parallel File Storage는 **읽기 전용 범위**(writes는
  `owner-exclusion` waiver class, owner 2026-06-12). 이 클래스들은 R3
  대상에서 빠진다.
- **계정 전제 부족** — bm-volume-group 등은 BM 서버(미보유) 필수,
  sqlserver는 라이선스 차단 등 — 환경 entitlement가 풀려야 검증 가능.
