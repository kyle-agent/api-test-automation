# 표기 가이드 — 화면 용어 정책 (D7 / 접목 6)

> **PROPOSED — 오너 문구별 검수 대기 (2026-07-13).** 이 문서는 CX-IA-DESIGN
> §4.0 원칙 2·D7("한글 1급 + 코드 보조")의 후속 산출물인 **1페이지 표기
> 가이드 제안**이다. **화면 반영 전 오너가 문구별로 승인해야 한다** — §5 검수
> 체크리스트에 O/X 를 표시해 주면 그 항목부터 화면에 적용한다. 승인 전까지
> 코드·화면은 현행 유지(이 문서는 지침만, 자동 적용 없음).
>
> 정의를 새로 만들지 않는다 — 정본(COVERAGE-CRITERIA.md, soft_classify.py,
> _badges.html)을 참조·정렬할 뿐이다. 충돌 시 정본이 이긴다.

## 1. 정책 (D7 — 승인 요청)

1. **한국어 1급 + 코드 괄호 보조.** 1급 화면 용어는 한국어로 쓰고, 코드/영문은
   괄호 보조로만: `검증됨(C3)` · `호출됨(C2)` · `도달가능(C1)` · `잔존 자원` ·
   `과금`. 코드가 헤드라인이 되면 안 된다 (`cov_op 62%` ✗ → `쓰기 검증 62%
   (cov_op)` ○).
2. **첫 등장 정의 툴팁.** C1/C2/C3·soft·known-red 등 등급 코드는 한 화면에서 처음
   나오는 요소에 한 줄 정의 툴팁: 예) "검증(C3) = 실제 2xx 로 동작 확인".
3. **내부 코드네임·env명은 화면 금지.** 계획 코드네임(§4)은 문서·커밋에만. 화면에
   노출할 값은 §3 용어집에 등재된 것만.
4. **배지 라벨은 영어 유지(예외).** 출처 배지 4종(Published/This server/This
   run/CI)은 donor 계약대로 영어 라벨 + 한국어 툴팁 — 짧고 국제 관용이라 유지
   (V1-GRAFT 결정 지점 3). 그 외 화면 지표는 모두 한국어 1급.

## 2. 세 층위 (W5 — 무정의 혼용을 정리)

화면에는 세 종류의 어휘가 섞여 있었다. **(a)·(b) 만 화면 노출, (c) 는 화면 금지.**

| 층 | 무엇 | 화면 | 예 |
|----|------|------|----|
| (a) | 도메인 등급·지표 | **노출 O** (한국어 1급 + 코드 보조 + 정의 툴팁) | C1/C2/C3, cov_op, soft, known-red |
| (b) | 출처·상태 표기 | **노출 O** (§3-2) | Published/This server, LIVE/SNAPSHOT, 판정/발행 |
| (c) | 내부 계획 코드네임 | **금지** — 문서/커밋 전용 | M3 §4-A1, R2c, C4/C5(계획), P2C-*, D1~D8, HB*, 접목 N, RESOURCE-MODEL 경로 2 |

## 3. 용어집 (화면 표기 정본)

### 3-1. 커버리지 사다리 (정본: `docs/COVERAGE-CRITERIA.md` — 재정의 금지)

| 화면 표기(1급) | 코드 | 한 줄 정의(툴팁) |
|---|---|---|
| 정의됨 | C0 / total | 카탈로그에 존재 (분모 1,372, 절대 안 줄어듦) |
| 도달가능 | C1 / reachable_pct | enabled 시나리오가 정적으로 도달 가능 (라이브 호출 없음) |
| 호출됨 | C2 | 실제 런이 호출해 HTTP 응답을 받음 — 4xx 포함 ("호출은 된다") |
| 검증됨 | C3 / cov_c3 | 실제 런에서 의미상 성공(GET→2xx, 쓰기→2xx) — **헤드라인** |
| 쓰기 검증 | cov_op | 쓰기(POST/PUT/PATCH/DELETE) 엔드포인트의 C3 비율 |
| 읽기 검증 | cov_get | GET 엔드포인트의 C3 비율 |
| 심화 | C4 | 2xx 하나를 넘어 상태코드·파라미터·스키마까지 (미구현) |

> **100% 목표** = waiver 아닌 모든 엔드포인트가 검증됨(C3), waiver 는 호출됨(C2).
> C1/C2 는 진척 지표지 목표가 아니다 (COVERAGE-CRITERIA §100% goal).

### 3-2. 출처·상태 (정본: `_badges.html`, base.html ctxbar)

| 화면 표기 | 뜻 | 색 |
|---|---|---|
| Published (배지) | 발행된 공식 집계 — 어느 서버에서 열어도 같은 값 | 파랑 |
| This server (배지) | 이 서버에서만 관측된 값 — 공식 집계와 다를 수 있음 | 초록 |
| This run (배지) | 특정 실행 1건에 고정된 값(과거형) | 보라 |
| CI (배지) | GitHub Actions 공식 런 기록 | 파랑 |
| **판정** @시각 | 이 수치를 낸 결과 런 시각 (history ts) | — |
| **발행** @시각 | 발행본이 갱신된 시각 — 결과 없이 재발행됐을 수 있음 (접목 5) | — |
| 노후 | 발행 스냅샷이 48h+ 지남 (STALE_AFTER_H) — 수치 회색화 | 노랑 |
| LIVE / SNAPSHOT | 이 화면 수치가 라이브 실측인지 발행 스냅샷인지 | — |

### 3-3. 실패·soft 분류 (정본: `regression/soft_classify.py`, known_issues.json)

| 화면 표기 | 코드 | 한 줄 정의 |
|---|---|---|
| 신규 fail | fail_new | baseline 에 없는 새로 깨진 5xx/auth — **진짜 회귀 후보(알림 대상)** |
| 알려진 실패 | known-red / fail_known | baseline(known_issues.json)에 등재된, 추적 중인 실패 |
| soft·정책 | policy | reachability-waiver 된 엔드포인트 (과금/권한 등 의도된 제외) |
| soft·중복 | duplicate | 같은 엔드포인트를 다른 데서 이미 2xx — 신규 정보 아님 |
| soft·갭 | gap | waiver 도 2xx 증거도 없음 — 레시피가 아직 못 덮음 |

> soft 우선순위(계약 고정): **정책 > 중복 > 갭**.

### 3-4. 자원·실행 (정본: resources.py, config 안전 게이트)

| 화면 표기 | 코드 | 한 줄 정의 |
|---|---|---|
| 잔존 자원 | owned scan | 우리 소유 태그가 붙은 채 계정에 남은 자원 (라이브 이 서버 관측) |
| 기지(항목) | stuck_resources | 문서화된, 현재 API 로 못 지우는 알려진 잔존 |
| 과금 | heavy | VM/K8s/DB 등 비용 발생 라이프사이클 (명시 opt-in 필요) |
| 변경 | mutation | POST/PUT/PATCH (읽기 아님) |
| 파괴 | destructive | DELETE |
| 미확인 | — | 아직 스캔 안 함 (≠ 0 — "0 아님" 병기, empty-state 규율) |

- [ ] **P1** 커버리지 사다리 한국어 1급 표기 (3-1) — `cov_op 62%` → `쓰기 검증 62%(cov_op)`
- [ ] **P2** C1/C2/C3 첫 등장 정의 툴팁 일괄 점검 (누락 화면 보강)
