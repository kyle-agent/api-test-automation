SCP Domain Knowledge (knowledge/)

Accumulated, human-readable knowledge about the SCP platform that the test agents need. AI agents generate and maintain it; humans read and adjust it. It is the durable memory that lets any new session start where the last left off. (이 디렉토리는 AI가 생성/유지하지만 사람이 읽고 수정하는 SCP 도메인 지식입니다.)

The same facts exist in two forms and must stay in sync:

  • Here (knowledge/*.md) — narrative, reviewable by a human.
  • As data (regression/scenarios/scenarios.json, dependencies.json, core/budgets.py, core/config.py) — consumed by the engines.

The Domain-Knowledge agent (docs/agent-team.md) owns keeping these two in sync. When you learn something, write it here and encode it in the scenario/budget data, in the same commit.

Provenance discipline

Every non-obvious fact is tagged:

  • VALIDATED — confirmed by a real 2xx at runtime (trust it).
  • from docs — taken from the API Reference, not yet runtime-confirmed (best-effort; verify before relying on it for mutations).

Never silently promote a "from docs" guess to VALIDATED — only a real success does.

Owner scope decisions (do not re-litigate per session)

  • storage/archivestorage — permanently excluded (owner, 2026-06-11): no dedicated auth keys will be issued; all 25 endpoints carry approved waivers, lifecycles stay enabled:false. Do not pull this service back in — if the key policy changes, the owner updates the decision first.
  • storage/parallel-filestorage — reads-only scope (owner, 2026-06-12): GET coverage only; writes are coverage-waived (owner-exclusion class) and the capacity-restore lifecycle is disabled. Recorded in formal/services/storage__parallel-filestorage.yaml.
  • Per-environment baselines are file-suffixed (known_issues.<profile>.json takes precedence over the default — core/baselines.py); multi-tenancy is a confirmed platform requirement (tenant columns exist in the control plane DB).
