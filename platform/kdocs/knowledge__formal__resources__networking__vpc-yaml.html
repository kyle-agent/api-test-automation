  vpc-endpoint:
    code: "nw-vpc-endpoint"
    service: networking/vpc
    # IB-013 (run 27466988779): the create needs a DEDICATED endpoint-type
    # subnet (subnet type=VPC_ENDPOINT), not the GENERAL subnet. The earlier
    # belief that the FS-volume resource_key alone resolves the subnet was
    # wrong — the 400 'scp-network.vpc-endpoint.subnet-not-found "VPC Endpoint
    # Type Subnet not found"' fires because subnet_id pointed at a GENERAL
    # subnet. So require the endpoint-subnet node (type=VPC_ENDPOINT) and wire
    # subnet_id to it. filestorage-volume stays the FS target resource_key.
    requires: [vpc, endpoint-subnet, filestorage-volume]
    create:
      endpoint: "POST /v1/vpc-endpoints"
      # resource_key is the TARGET service resource (an FS volume id here);
      # resource_info is free text describing it (api_docs: string, max 200).
      # subnet_id MUST be a VPC_ENDPOINT-type subnet (endpoint-subnet node).
      body: {name: "regrvpce{unique}", description: "API regression vpc endpoint",
             endpoint_ip_address: "{opt.endpoint_ip_address}",
             resource_info: "regrfs{unique}",
             resource_key: "{filestorage-volume.volume_id}",
             resource_type: "{opt.target}",
             subnet_id: "{endpoint-subnet.subnet_id}", vpc_id: "{vpc.vpc_id}", tags: []}
      options:
        target: {type: enum, values: [FS, OBS, SCR], default: FS,
                 required: true, vary: true,
                 note: "유효 enum은 라이브 ValidationError가 직접 알려줌(run 27394211896): 'VPC Endpoint Resource Type should be a valid types(FS, OBS, SCR)' — dns는 유효 타입이 아님 (VALIDATED enum). resource_key가 FS 볼륨 id로 배선되어 있으므로 OBS/SCR 변형은 각자의 실 자원 키로 재배선 전에는 합성 금지"}
