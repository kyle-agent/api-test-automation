# Resource-task model — storage/archivestorage (st-as group).
# Schema: docs/RESOURCE-MODEL-PLAN.md §1 · extracted from archivestorage-bucket +
# archivestorage-archiving-policy.
#
# REACHABILITY-ONLY COVERAGE (owner override, 2026-06-16). archivestorage was
# previously PERMANENTLY EXCLUDED (needs its OWN console-issued 인증키 — IAM My
# Info > 인증키 관리 — that this test account will never have; every call 401s
# with platform HMAC creds alone). The owner has now reframed it as a
# REACHABILITY-ONLY target: every endpoint is CALLED regardless of the result —
# the point is to test ACCESS/REACHABILITY, not real resource creation. So the
# nodes below are coverage-only (mirroring the management/organization
# org-*-guarded pattern): every write/GET is `optional` with a tolerant
# `expect_status`, 4xx is EXPECTED and TOLERATED, no real creation is expected
# (no archivestorage key), and any write that COULD 2xx carries a tolerant
# teardown delete so a stray success never leaks. provenance stays `docs` — these
# are NOT 2xx-validated; they are reachability probes.
#
# CHANGED vs the prior model: the `{credential: archivestorage-auth-key}`
# requires gates were REMOVED — reachability deliberately calls WITHOUT the key
# (the no-key 4xx IS the evidence the endpoint is reachable). The owner-exclusion
# waivers were dropped from data/baselines/coverage_waivers.json in the same unit.
