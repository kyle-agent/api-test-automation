# Resource-task model — management/iam-identity-center (mg-idc group, SSO).
# Schema: docs/RESOURCE-MODEL-PLAN.md §1 · extracted from the idc-* lifecycles.
#
# REACHABILITY-ONLY COVERAGE WITH A SAFETY RAIL (owner override, 2026-06-16).
# IdC was previously ALL-disabled (service excluded from the C3 target, waived in
# coverage_waivers.json). The owner has now reframed it as a REACHABILITY-ONLY
# target (same shape as storage/archivestorage): every IdC write + id-bound GET
# is CALLED regardless of the result — the point is to test ACCESS/REACHABILITY,
# not real SSO config. So each write/GET below is an `optional` step with a
# tolerant `expect_status` ([...,400,403,404,409,422]); a 4xx is EXPECTED and
# TOLERATED (reachability = the endpoint RESPONDED, even 4xx, NOT a successful
# grant). provenance stays `docs` — these are reachability probes, NOT validated.
#
# CRITICAL SAFETY — IdC writes can mutate ACCOUNT-LEVEL SSO config IF they
# succeed. The reachability calls MUST 4xx WITHOUT creating/granting real config:
#   * create-instance: the body is the docs-sample LDAP bind to a NON-EXISTENT
#     test directory (bind_dn/connection_url point at test.subdomain.company.com)
#     so it ValidationErrors/403s rather than persisting a real SSO instance; it
#     carries a tolerant teardown DELETE so any stray 2xx is torn down.
#   * users/groups/permission-sets: instance_id is the SYNTHETIC placeholder
#     ssoins-12345 (NO real instance) so creates 4xx; by-id GET/PATCH/PUT/DELETE
#     key off captured-soft ids that never resolve to real objects (4xx). Group
#     add/remove-users send EMPTY user_uuids[]; policy arrays are EMPTY.
#   * account-assignment (MOST SENSITIVE — grants a principal a permission-set on
#     a target account): the body uses ALL-ZERO synthetic ids
#     (target_account_id/permission_set_id/principal_id = 32 zeros) + synthetic
#     instance_id so it CANNOT create a real grant. We deliberately do NOT wire
#     real node ids into the live account-assignment create.
# NO real SSO instance and NO real account assignment is created. The entitlement
# (owner-exclusion) waivers were dropped from data/baselines/coverage_waivers.json
# and the idc-* lifecycles were enabled in the same unit.
#
# NOTE: the model below keeps the curated {iam-identity-center.instance_id} /
# node-reference wiring as the DEPENDENCY-SHAPE documentation for a future
# dedicated org-management test account (R3+); the ENABLED lifecycles use the
# synthetic/all-zero ids described above for safe reachability.
version: 1
resources:
  iam-identity-center:
    code: "mg-idc-instance"
    service: management/iam-identity-center
    heavy: true
    requires: []
    create:
      endpoint: "POST /v1/instances"
      body:
        name: "regridc{ualpha}"
        description: "API regression suite SSO instance"
        identity_store_type: "{opt.identity_store_type}"
        identity_store_config:
          bind_credential: password
          bind_dn: "CN=Administrator,CN=Users,DC=test,DC=add"
          connection_url: "ldaps://test.subdomain.company.com:123"
          rdn_ldap_attribute: cn
          user_object_classes: "person, organizationalPerson, user"
          username_ldap_attribute: sAMAccountName
          users_dn: "OU=Employees,OU=Accounts,DC=sub,DC=org"
      options:
        identity_store_type: {type: enum,
                              values: [ACTIVE_DIRECTORY, IDENTITY_CENTER_DIRECTORY],
                              required: true, default: ACTIVE_DIRECTORY, vary: true,
                              note: "identity source. ACTIVE_DIRECTORY 분기는 identity_store_config(LDAP) 필요 — 소스 body는 api_bodies createinstance의 doc 샘플 그대로(실 AD 아님). IDENTITY_CENTER_DIRECTORY는 config 불필요 추정. identity source 변경은 기존 사용자/그룹/할당 전체 삭제 (identity-source-change-wipes-everything)"}
    capture: {instance_id: "$.instance.id"}
    delete: {endpoint: "DELETE /v1/instances/{instance_id}", destructive: true}
    provenance: docs
    source: {lifecycle: idc-instance, steps: [create-instance, delete-instance]}
    notes: "cross-service 노드 키 iam-identity-center. Organization MANAGEMENT 계정만 생성 가능 (Organization 선행 — 엔타이틀먼트 사전조건이라 requires 엣지가 아닌 note로 기록; cross-service requires []와 일치). 단일 region, kr-south3 미지원 — 스모크 400의 원인. BLAST RADIUS: instance는 모든 SSO 사용자/그룹/permission-set의 기반, 삭제는 cascade (delete-cascades). capture envelope $.instance.id는 소스에서 capture_soft 추정 — UNPROVEN."

      body:

        user_id: "regridc{ualpha}"
        name: "API Regression User"
        email: "regr-test@example.com"
        description: "API regression suite SSO user"
        department: QA
        business_unit: Automation
        manager: "Regression Bot"
        employee_id: "regr-{unique}"
        nation_id: "+82"
        phone_number: "010-1234-5678"

        password: ""
        group_ids: []
    capture: {user_uuid: "$.user.id"}
    delete: {endpoint: "DELETE /v1/users/{user_uuid}", destructive: true}
    provenance: docs
    source: {lifecycle: idc-user, steps: [create-user, delete-user]}
    notes: "소스는 instance_id에 docs placeholder(ssoins-12345)를 보냈다 — 실소유 instance 주입은 이 모델이 처음 제공 (private-nat 패턴). body createuser 기반, capture $.user.id capture_soft 추정 — 모두 UNPROVEN. 경로 /v1/users는 iam 계열과 path-root 공유 — per-service host 필수. MFA 필수 정책 주의 (mfa-mandatory)."
