# Schema: docs/RESOURCE-MODEL-PLAN.md §1 · extracted from the epas-* leg of
# heavy-shared-dbaas. Unlike the maria (run e3ba190 delete timing) and cache

# 2026-06-13 확장 — database__postgresql.yaml 레퍼런스 패턴 미러링 (replica

# 2026-06-14 EPAS userguide WebFetch (overview/readreplica/backupandrestore/
# managing) — 2회차 정제 동봉. PG에서 '준용/추정'했던 항목을 EPAS 문서로 직접 확정:
#  · EOS/EoTS 표: 14.x EOS 2026-05-20(현재일 경과 — 14 라인 신규생성 중단 가능),
#    15.x EoTS 2028-02-13, 16.x 2028-11-09, 17.6 2029-11-08; 15.15/16.11/17.17은 2026-07+.
#  · replica name = 소문자/숫자/하이픈 3-19자 (PG 3-20과 다름); 복제 개수 입력 2-5.
#  · restore: 복구 클러스터는 네트워크 미상속(IP 접근제어 재설정 필요) — PG와 차이.
#  · archive 보존 기본 = 3일 (managing); 모델 body는 PG verbatim 7일 유지(라이브 정제).
#  · 엔진 버전 = EPAS 전용 라인 14.17-14.19 / 15.12-15.14 / 16.8-16.10 / 17.6
#    (PG 16.10/17.6와 다름; EPAS는 14·15 메이저도 노출, EoTS 6개월 전 신규생성
#    중단). engine-version-16 필터는 EPAS 16.8-16.10 범위로 확정.
#  · 선행: VPC(+subnet) 필수 (overview prerequisites).
#  · server-type = [Category][Spec][vCore][Memory], Standard=db1 / High
#    Capacity=dbh2(24+ vCore) (overview/servertype).
#  · replica: 동일 리전·최대 5개/DB, cross-region은 'Other Region' 별도 변형
#    (DR용); promote 비가역; reset = 망/지연 시 재복제 (PG와 동일 — EPAS 문서로
#    재확정).
#  · restore: 백업은 예약 수행(즉시 아님), PITR 5/10/30분·1시간 증분, archive
#    보존 1-35일; 신규 서버 생성; DATA 디스크 ≥ 원본 필요. ★PG와 차이: EPAS
#    backupandrestore 문서는 '완료된 첫 백업 선행 필수'를 명시하지 않음
#    (드롭다운/시점선택만) — restore 게이트는 보수적으로 유지(라이브 정제).
#  · managing: 마이너 업그레이드는 동일 메이저 내만, replica 먼저, 사전백업은
#    완료 후 자동삭제; kernel/OS 업그레이드 = 중단·실패 시 원복·성공 시 비가역;
#    log export는 OBS 버킷+인증키(만료 시 적재 중단). switchover = HA 전용.
